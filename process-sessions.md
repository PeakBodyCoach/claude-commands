## Steps

### 1. Discover work

List `.md` files directly in `_inbox/` (NOT inside `_inbox/_processed/`). Also check `_inbox.md` for non-template content.

If both are empty, report "Nothing to process." and stop.

### 2. Process each per-session file in _inbox/

For each session file:

#### 2a. Parse filename

Format: `YYYY-MM-DD HHMM Client Name.md`. Extract:
- `date` — YYYY-MM-DD
- `time` — HH:MM (insert the colon back)
- `client_name` — everything after the time, before `.md` (use as canonical name; verify against roster, fuzzy-match if needed)

#### 2a-guard. Skip future sessions

Compare the session's date+time against the current date and time. If the session is scheduled in the future (i.e. `datetime(date, time) > now`), **skip the file entirely**: do not move it, do not archive it, do not process it. Report it as `skipped (future session — [datetime])`.

This prevents empty session files from being archived as "unrecorded" before the session has happened.

#### 2b. Extract sections

Find these section headings in the file:
- `## Live Notes` — read until the next `## ` heading
- `## Voice Notes` — read until end of file or next `## ` heading

Inside the **Live Notes** section, parse each prompt:
- `**Changes made:**` — content until next `**Prompt:**` line or section break
- `**Form notes:**` — same
- `**Tasks / follow-ups:**` — same
- `**For next session:**` — same
- `**Khaela report:**` — same

Trim whitespace. A prompt with no content (just the colon and a blank line) is treated as empty.

The **Voice Notes** section is free-form text. May be empty, may contain transcribed dictation. Treat it like a voice-note transcript.

If both Live Notes and Voice Notes are empty (all prompts blank, no voice notes), the file represents an unrecorded session. Move it to `_processed/` with no further action. Report it.

#### 2c. Read client history

Open `[Client Name] - Session Log.md`. Find `## Session Log` and read the 3 most recent `### ` entries below it. Use these for recurring-themes detection.

#### 2d. Extract structured fields

Combine Live Notes + Voice Notes content. From the combined content, extract:

- **exercises**: list of exercises mentioned
- **flagged_body_parts**: body parts with pain/issues/tightness/restriction
- **rpe_notes**: RPE/RIR values mapped per exercise where possible (e.g. `{squat: 8, bench: 7}`)
- **mood**: client's stated mood/energy/state if mentioned (omit if not stated)
- **life_events**: external life things — travel, illness, work stress, sport, sleep, family
- **program_changes**: explicit programming changes for next session. Pulled from Live Notes `**Changes made:**` + `**For next session:**` + any voice-note mentions of "next time", "going to N kg", etc.
- **tasks**: actionable follow-ups for Tom. Pulled from Live Notes `**Tasks / follow-ups:**` + any voice-note action items.
- **khaela_report**: content from Live Notes `**Khaela report:**` + anything voice-note-flagged for Khaela
- **recurring_themes**: anything in this session AND in 2+ of the previous 3 sessions read in 2c. Format: `[theme] — [count]th mention this period`.

Omit empty fields. Don't fabricate.

#### 2e. Insert into Session Log

Open `[Client Name] - Session Log.md`. Find `## Session Log` and insert the new entry directly below it (so it becomes most-recent).

Workout type: parse from per-session-file header or filename context if specified (e.g. if Today's Plan showed "Workout C"). Otherwise default to `Session`.

Format:

```markdown
### YYYY-MM-DD — [Workout Type]
exercises: [squat, bench, pendlay row]
flagged_body_parts: [shoulder]
rpe_notes: {squat: 8}
mood: tired
life_events: [racquetball injury Friday]
program_changes: [bench → 82.5kg next session]
recurring_themes: [shoulder twinge — 2nd mention this month]

- Form notes content (from Live Notes Form notes prompt, plus relevant voice-note bullets)
- Other bullets from voice notes, cleaned (sentence case, punctuation, not reworded)
```

The bullets below the structured block carry the narrative content: Live Notes `**Form notes:**` content, plus cleaned voice-note bullets. Don't duplicate program_changes / tasks here — they're already in the structured fields.

If the file has no `## Session Log` heading, append one and place the entry beneath.

#### 2f. Update sessions.csv

The session row should already exist with `status = scheduled` (created by `/sunday-booking-workflow` or `/add-session`). Flip to `complete`:

```bash
python "C:\Users\Tom\.claude\skills\_shared\sessions_io.py" set_status "<client_name>" <date> <time> complete ""
```

If no matching scheduled row exists (shouldn't happen for files generated by the new system, but defensive): append a new row with `status = complete`, using the existing append flow from the legacy logic below.

#### 2g. Update client Bookings.md

If `[Client Name] - Bookings.md` exists:

1. Remove any row matching this date from the Upcoming table.
2. Prepend a row to the History table: `| YYYY-MM-DD | HH:MM | regular/flexible | (notes) |`.
3. Skip silently if file doesn't exist.

#### 2h. Append tasks to tasks.md

For each item in `tasks`, append a line under `## [Client Name]` heading in `tasks.md`:

```
- [ ] [task description] ([today's date])
```

If the section exists, insert directly below the heading (most recent first). If the section doesn't exist, create it at the bottom of the file.

Don't duplicate tasks that already appear word-for-word in the section.

#### 2i. Archive the file

Move the per-session file from `_inbox/` to `_inbox/_processed/`. Keep the same filename.

### 3. Process the legacy _inbox.md (fallback)

If `_inbox.md` has non-template content, run the parsing logic for each `# ClientName` block as before:

- Normalise headers (strip punctuation, fuzzy-match name, parse workout type, date defaults to today)
- For each block: read client history, extract structured fields, insert into Session Log
- Update sessions.csv:
  - If a matching scheduled row exists for the date+time+client: use `set_status` to flip to `complete`
  - Otherwise append a new row (column order: `date,time,client_name,status,regular_flexible,location,week_number,rate_at_time,credit_burn,notes`)
- Update Bookings.md per step 2g
- Append tasks per step 2h
- Add to Khaela report

After all matched blocks processed, reset `_inbox.md` to its template state:

```markdown
# Today's session notes

Paste voice notes below. First dictation of each session is the header (e.g. "Rich Radley, Workout B, April 27").
```

Preserve any UNMATCHED blocks at the bottom of the file with `# UNMATCHED:` prefixed.

### 4. Generate Khaela's daily report

Write a single consolidated markdown file covering ALL sessions processed in this run (both _inbox/ files and _inbox.md blocks):

`$VAULT_PATH/2 - Business/Operations/Khaela/_session-reports/[YYYY-MM-DD].md`

Create the `_session-reports/` folder if it doesn't exist.

If a report already exists for today (e.g. /process-sessions has been run earlier and is being re-run for additional sessions), append the new content to the existing file rather than overwriting.

Content:

```markdown
# Session Reports — [Today's Date, friendly format]

@Khaela — session notes below. Transcripts are at the bottom.

---

## [Client Name]
**[YYYY-MM-DD] — [Workout Type]**

[2-4 bullets covering key things that happened. Plain prose, no field syntax.]

**Programme changes:**
- [Specific change to make in OneFit or the written programme]

**To do:**
- [Actionable task for Khaela]

---

## Transcripts

### [Client Name] — [YYYY-MM-DD]
[For per-session files: dump the Voice Notes section content. For _inbox.md blocks: dump the original voice-note text.]
```

Rules:
- Per-client summary in plain sentences/short bullets — no `exercises: [...]` field syntax
- Use the `**Khaela report:**` prompt content as the seed for the summary if present; supplement with voice-note details
- Omit "Programme changes" and "To do" headings if there's nothing to action
- For cancellations with no session content: one sentence
- Each client block short enough to scan in 10 seconds
- Transcripts section: include Voice Notes content from per-session files AND the original voice-note text from any _inbox.md blocks. Skip if a session had no voice notes.

## Edge cases

- **Future session file** (session date+time is in the future): skip entirely, leave in `_inbox/`, report as "skipped (future session)". This applies even if the file is empty — it hasn't happened yet.
- **Empty per-session file** (all Live Notes prompts blank, no Voice Notes, and session is in the past): move to `_processed/`, no Session Log entry, no sessions.csv update. Report as "empty (archived)".
- **Per-session file for a date that's not today**: process as normal — date comes from filename, not today's date. This handles late processing (e.g. processing Monday's files on Tuesday).
- **Multiple sessions same client same day**: each gets its own per-session file (distinct times in filename), each becomes a separate dated entry in Session Log.
- **No exercises mentioned**: process as Check-in (sparse structured fields, that's fine).
- **Whisper artifacts** (filler words, repetitions, "um" "uh"): strip silently during cleanup of Voice Notes content.
- **Known mistranscription**: "kill" → "curl" (Whisper consistently mishears "curl" as "kill" — always substitute silently).
- **Client file has no Session Log heading**: append the heading and insert beneath.
- **Unmatched per-session file**: leave in `_inbox/`, don't archive. Tom will fix the filename or rename the client folder.
